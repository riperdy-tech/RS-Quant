### Contradictions resolved conservatively

- The current instrument catalog uses `/api/v3/market/instruments`; the [upgrade guide](https://www.bitget.com/docs/classic/uta-api-upgrade-guide) and best-practices guide still mention `/api/v3/public/instruments`. This adapter pins `/market`, with `quantityMultiplier` and `priceMultiplier`; it does not silently switch APIs.
- V3 login prose/JavaScript use milliseconds, while legacy Java/sample fragments use seconds. The adapter pins integer **milliseconds** and `timestamp + GET + /user/verify`. External authentication remains unverified; it never retries by guessing another unit.
- Current place-order documentation requires explicit `marginMode=isolated` for isolated orders although migration text suggests changed margin-mode handling. The adapter emits the explicit field and blocks unsupported profiles.
- Public JSON trades use `i/L/p/v/S/T`, not Classic `tradeId/price/size/side/ts` or SBE fields. `i` is execution identity; `L` is correlation metadata, not an economic alias.
- Order best-practices prose calls fills `tradeId`; the dedicated V3 REST/WS fill schemas use `execId` and separate `execLinkId`. Only exact `execId` is deduplicated; correlation IDs are never guessed aliases.

## Transport and security contract

REST HMAC-SHA256 is base64 of the exact UTF-8 bytes: integer millisecond timestamp, uppercase method, encoded request path plus `?query` if present, then body bytes. Query keys are sorted and URL-encoded once; the same target/body are transmitted. JSON body strings preserve Decimal precision. No GET body is signed. Authentication headers are excluded from capture; login frames are excluded entirely. Private request/response/WS bodies require injected encrypted `RawJournal` storage and are durable before normalization or writer authorization.

DEMO HTTP must be loopback. Default real DEMO WebSockets require an explicit loopback origin; a scripted injected connector is the other supported local boundary. Tests reject nonloopback DNS before sockets. PAPER/SHADOW cannot carry private credentials. SANDBOX requires explicitly classified demo credentials and independently enabled sandbox writes; REST adds `paptrading: 1`, WS uses `wss://wspap.bitget.com/v3/ws/{public,private}`. No account settings, transfer, withdrawal, or dead-man route is write-allowlisted. The documented ordinary `ws.bitget.com` hosts are not contacted by automated tests.

Every potentially yielding step (rate permit, connect, safe journal write) happens during preparation. The real HTTP transport opens a bounded socket then, after the account writer's final risk/fence/expiry revalidation, `handoff` synchronously calls `StreamWriter.write` with the complete freshly signed request. It returns an awaitable **only for response receipt**. Coroutine-function handoffs are rejected. Known-unsent cancellation/revalidation clears permits and prepared sockets; a lost response never causes a fresh-ID resubmission.

The writer retains its known-unsent capability through all synchronous pre-byte checks. A typed `KnownUnsentError` covers expired preparation, revoked profile, changed encoded instruction, missing prepared socket and encoding/signing failure; it releases the claim without fabricating venue uncertainty. Once the byte handoff starts, an ordinary transport exception or response timeout remains UNKNOWN. Failed WS setup always closes its partial connection; semantic private quarantine and journal-runtime failure invalidate readiness immediately. Semantic quarantine also drops the cached eligible account profile.

The documented timestamp acceptance is within 30 seconds. A stricter local prepare-age budget defaults to 5 seconds (configurable up to 30 seconds); stale/backward preparation fails before bytes. This is not a fabricated receive-window header. Clock/auth errors block; no implicit clock adjustment occurs. Request and response times remain integer boundaries. Receipt wall and monotonic clocks and original connection epochs are preserved separately.

HTTP 200 is not venue acceptance: REST requires string code `00000`. HTTP 429/rate codes are throttle errors; authentication/clock failures do not retry. 5xx and `40010`, `40725`, `45001` are ambiguous submission outcomes. Other nonzero order responses are explicit rejections. Truncation, timeout, disconnect, malformed successful response, or identity mismatch after send remains unknown. Read-only transient calls have three bounded attempts (0.5s, 1s delays); order POSTs are not automatically retried.

Separate endpoint buckets use 10 requests/sec for ordinary/strategy writes, 20/sec for recovery reads and instruments, 5/sec for account info, and 3/sec for fee rates, plus 6000 REST requests/minute/IP. This adapter is one account writer; multiple independent processes must share the venue/IP budget operationally. WS connection budget is 300/5min, control budget 10/sec/connection, subscription budget 240/hour/connection; six public and four private topics remain below the recommended topic count. Literal `ping` is periodic even under busy incoming traffic; missing `pong`, invalid messages, buffer overflow, or disconnect invalidates readiness. Reconnection is explicit and bounded with backoff, resubscription and a new epoch; private reconnection always requires account recovery.

## Normalization and completeness

The release subset is BTCUSDT/ETHUSDT linear perpetuals, USDT settlement, explicit isolated margin, one-way positions, and LIMIT GTC/IOC/FOK/POST_ONLY. Quantities and prices are exact string-to-Decimal-to-integer-lot/tick conversions, with no rounding. Instrument online status, multipliers, precision, min/max quantity, min notional, leverage limits and funding interval are preserved. A documented zero/unbounded maximum or missing required filter is unsupported unless a separately reviewed conservative contract is supplied. Unbounded MARKET, spot/margin, inverse, delivery, hedge, cross/portfolio collateral and automatic borrowing are not enabled.

`books` starts with snapshot then absolute level replacement deltas; zero quantity deletes. `seq` is increasing but **not contiguous**. The first delta must cover snapshot `seq` within `[pseq, seq]`; later deltas require exact previous `seq == pseq`. `pseq=0` reset, missing/malformed evidence, gaps or reordered updates fail closed and require a new snapshot. `books1/5/50` are snapshot-only feeds. No V2 checksum or snapshot completeness is inferred. Instantiate one `BitgetBookSequence` per real `BookBuilder`; never share its alignment state between instruments.

Private order/fill streams do not provide a complete initial set. Subscription acknowledgements are required before placement. Account/position stream messages are audited observations, not cross-endpoint atomic snapshots; an empty/nonzero-only push cannot erase local state. Exact fills, maker/taker flags, signed fee values, native PnL, IDs and millisecond timestamps are normalized. V3 examples report positive fee costs; negative values remain explicit rebates, without importing Classic sign conventions. Account-specific fee-sign acceptance is still an external check. Multiple fee currencies in one fill are rejected for review rather than silently summed.

Reconnect invalidates the previous eligible account profile. Profile discovery and recovery scan USDT-, COIN- and USDC-futures positions. Conditional-order discovery scans `usdt-futures`, `coin-futures`, `usdc-futures`, `spot` and `margin`; an empty USDT response cannot conceal a foreign conditional order. Profile, protection capability and instruction filters are checked again after asynchronous transport preparation; revoked/invalid requests release their known-unsent claim without sending.

REST open orders, histories, fills and financial records must return explicit `data.list`. Every page is journaled. Continue following the returned string cursor until an explicit empty list; short nonempty pages are not completion. Missing/repeated cursors, invalid shape or page budget exhaustion block recovery. History/fills/financial requests use at most 30-day spans within 90-day retention. Recovery overlaps its committed time cursor by 60 seconds; pagination cursors are transient request details. Position snapshots require `data.list`, explicit category, `total == available + frozen`, side and mode checks. Financial categories are scanned, including OTHER; foreign activity is retained and blocks the supported account.

Funding uses identified funding-record enums and signed amounts. Transfers are non-trading cash flows. Trade cash records are corroboration, not a second fill/fee posting. Unknown corrections, rebates or cash movement types remain raw-linked observations and block; only a reviewed canonical ledger adjustment can resolve unsupported corrections. No snapshot writes balances or positions.

Ordinary `orderStatus=live` maps to canonical OPEN. Both REST and private order rows preserve canonical contract evidence: instrument, integer quantity/price units, side, order type, time-in-force, reducing flag, margin and position modes. The account writer independently binds this evidence to the committed instruction and native order identity. Missing/conflicting fields or an unknown contract revision remain durable conflicts requiring review; a later matching snapshot does not silently erase them. The complete venue open set must equal the locally active, transport-started order set before convergence or flat confirmation.

## Recovery and native protection

Register `execution_reducer`, `recovery_reducer`, `protection_reducer` and `protection_producer` with the single account engine. `Reconciler.run()` returns a `ReconciliationReport`/`RecoveryProgress`. It first durably latches entries and records RECONCILING, then establishes buffered private streams, obtains all REST pages, resolves each original committed client ID, applies economic facts through the real OMS/ledger, drains buffered input, and compares observations. Unknown/missing execution details retain reservations and the original identity. Foreign orders are never automatically canceled.

Two economically/control-equivalent observations at least one second apart are required; the bounded default is 30 seconds. Quantity must match exactly; wallet tolerance is the explicit settlement rounding unit (initial conservative USDT policy `0.00000001`, requiring external account verification). On failure the old durable cursor remains, and discrepancies/raw observation IDs remain append-only facts. Cursor advancement occurs only after all fact commits and convergence. Account convergence does **not** clear the entry latch, establish book freshness, acknowledge the recovery gate, or enable LIVE; those are separate Task08/runtime authorities.

Opening onboarding permits only an empty local ledger, dedicated flat eligible account, no open/foreign protection, and stable observations. The opening USDT wallet is booked once as identified `opening-flat-v1` non-trading cash, with both observation sets retained. New economic activity during onboarding blocks rather than being counted again in the baseline. Checkpoint/tail replay and retry cannot duplicate this identity.

Attached entry stop fields (`stopLoss`, `slTriggerBy=mark|market`, `slOrderType=market`) are implemented. A non-reducing order needs an eligible profile and explicit reviewed protection-capability evidence; none is provided by default. Native child-to-group ownership bindings are separate evidence, never inferred from matching symbol/price. Verification checks owned position quantity, trigger basis/value, pending state, market stop and association; TP and SL quantities are never added.

Safe native coverage additionally requires the matching instrument and current position side, and explicit `reduceOnly=yes` evidence. Absent/negative reducing evidence is unsupported, even with a bound native ID. Invalid/unparseable legs cannot yield PROTECTED; their raw-linked observations are retained and the actual owning group requests restoration/exit as applicable. Protection ownership follows committed executions through actual flat/reopen cycles, with duplicate/alias executions unable to revive an old group. Inactive historical groups never inherit a later position. Multiple independent groups in the same exposure cycle, or missing ownership evidence, remain blocked rather than assigning the full position to each group.

`ProtectionReview` is processed by the real immutable engine: coverage, deadline and desired quantity become rebuildable protection projections; reports, latches and typed `ProtectionActionsRequired` are deterministic facts. Missing/invalid protection requests entry cancellation and restoration within the configurable 2-second budget; failure requests a bounded reduce-only exit. Partial closes request resize without first canceling the existing stop. Uncertain flat retains protection; confirmed flat requests stale-stop cleanup and reconciliation. Pause/cancel-entry is not cancel-protection.

Flat confirmation itself requires two stable matching REST/ledger observations with no open ordinary orders. An owned pending native stop then produces a durable cleanup request and `STALE_PROTECTION` block, not cursor advancement. A later reconciliation must observe cleanup before account convergence.

Current redirected strategy pages do **not** establish a trustworthy standalone place-strategy schema or `tpslMode` contract. Standalone placement is therefore rejected and not write-allowlisted. Native modify/cancel schemas are documented but are not an unfenced trading bypass: cancellation is identified by orderId OR clientOid (no invented category/symbol); actual emergency action authorization, timers, bounded exits and residual tracking are the explicit Task08 consumer. Until account-level coexistence, partial-fill resizing, child linkage and close-reversal prevention are independently verified, the production protection profile remains unavailable and restoration fails closed. The default does not claim a protected live account.
